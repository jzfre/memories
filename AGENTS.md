# Repository privacy

- Keep all source, tests, examples, documentation, and work journals generic.
- Never include the owner's real project names, client directory mappings,
  hostnames, deployment domains, credentials, or private vault content here.
- Use `personal`, `work`, and `family` for vault examples. Vault IDs remain
  configurable; these examples must not become an application whitelist.
- Keep actual deployment and client mappings in private configuration outside
  this repository. Store owner-specific operational facts in the authorized vault.
- Do not record prohibited names in regression tests or cleanup notes. Verify
  privacy with an external, ad hoc scan instead.
